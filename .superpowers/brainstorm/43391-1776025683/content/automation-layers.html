Como os cards se movem "magicamente"

Duas camadas de automação — uma é grátis e nativa, a outra exige uma skill no Claude Code

✅ Camada 1 — GitHub nativo (zero config extra)

O GitHub Projects já detecta eventos do repositório automaticamente:

► PR aberto → em-desenvolvimento → pull-request
► PR merged → pull-request → producao
► CI passa / falha → label no card visível no board
► Issue fechada → → Done

⚡ Camada 2 — Claude Code move os cards (requer skill/hook)

Para mover upstream (backlog → ideação → definição técnica → em-desenvolvimento), o Claude precisa chamar a API do GitHub Projects. Isso é configurável via skill ou hook no Claude Code:

► Claude começa a trabalhar na feature → backlog → em-desenvolvimento
► Claude cria o PR → → code-review (automático via GitHub)
► Você aprova o PR → → producao (automático via GitHub)

Resumo prático

Com configuração mínima (GitHub Workflows + uma skill no Claude Code), você abre o Projects e vê os cards se movendo enquanto o agente trabalha. A parte "verde" é nativa — PR aberto e merged move sozinho. A parte "amarela" exige um hook que o Claude chama ao iniciar/concluir cada etapa.
