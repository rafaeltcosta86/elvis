Ferramentas existentes para o seu PDLC

Qual dessas se encaixa melhor no seu fluxo de desenvolvimento agent-driven?

A

Linear

Melhor UX do mercado para dev. Cycles, Workflows customizáveis com quantos estágios quiser, integração nativa com GitHub (PRs aparecem automaticamente na issue). Keyboard-first, extremamente rápido. Free até 250 issues.

Pros

  • Workflow com estágios livres (seu PDLC completo)
  • PR/build linkado à issue automaticamente
  • API REST + Webhooks → agentes podem mover cards
  • Melhor UI de kanban do mercado

Cons

  • SaaS — dados na nuvem
  • Free tier limitado a 250 issues (suficiente pra você)
B

GitHub Projects (v2)

Zero fricção — você já usa o GitHub. Columns customizáveis, automação nativa (PR aberto → move para "pull-request", merged → "produção"), workflows via Actions. Vive dentro do repo.

Pros

  • Totalmente integrado ao repo Elvis
  • PR aberto/fechado move card automaticamente
  • 100% gratuito
  • Issues e PRs são os próprios cards

Cons

  • UI mais pesada que Linear
  • Automações exigem configurar GitHub Actions
  • Sem "upstream" de ideação nativo
C

Plane.so

Open-source, self-hosted, Jira-killer. Estágios completamente livres, Cycles, Modules, integração GitHub. Pode rodar no mesmo VPS do Elvis.

Pros

  • Self-hosted no VPS da Hostinger
  • Dados locais, zero custo
  • Estágios completamente personalizáveis
  • Interface moderna, próxima do Linear

Cons

  • Você mesmo mantém (updates, backup)
  • Setup inicial no VPS (~30min)
  • Integração GitHub menos madura que Linear

Ponto-chave da sua necessidade

Você quer ver o status em tempo real enquanto os agentes desenvolvem. Isso exige que a ferramenta tenha API ou webhook para que o Claude Code mova os cards automaticamente conforme avança pelas etapas do PDLC.

Linear e GitHub Projects têm isso nativamente. Plane tem API mas requer mais trabalho.
